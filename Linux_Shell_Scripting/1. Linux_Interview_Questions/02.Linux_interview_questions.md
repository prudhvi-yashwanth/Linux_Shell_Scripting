# Linux + DevOps Scenario-Based Q&A — Day 1 to Day 15

---

### Q: You SSH into a server and need to quickly confirm your current location and which user you're logged in as. What do you run?
**A:**
```bash
pwd
whoami
```

---

### Q: You need to find and delete every `.tmp` file under `/var/cache` older than 7 days — but want to preview matches before deleting anything.
**A:**
```bash
# Preview first
find /var/cache -name "*.tmp" -type f -mtime +7

# Once confirmed, delete
find /var/cache -name "*.tmp" -type f -mtime +7 -exec rm {} \;
```

---

### Q: A teammate hands you `payload.json` but your script fails parsing it. What's the first command you'd run, and why?
**A:**
```bash
file payload.json
```
Extensions can lie — `file` inspects actual file content/type, revealing if it's really binary, gzip, etc. instead of plain text.

---

### Q: You run `./deploy.sh` and get `Permission denied`. Walk through the fix.
**A:**
```bash
ls -l deploy.sh        # confirm it lacks execute permission
chmod +x deploy.sh      # add execute permission
./deploy.sh              # run it
```

---

### Q: A script exists in the current directory but running `deploy.sh` gives `command not found`, even though `ls` shows it. Why, and what's the fix?
**A:**
Current directory is not in `$PATH` by default (a security convention). Run it explicitly with a relative or absolute path:
```bash
./deploy.sh
```

### Q: During an incident, a service just crashed. What's the very first command you run, and why?
**A:**
```bash
tail -f /var/log/syslog
# or, for a specific systemd service:
journalctl -u <service> -f
```
Watching logs live is the fastest way to see what's happening right now before touching anything.

### Q: A production disk-space alert fires. Walk through tracking down what's eating the space.
**A:**
```bash
du -sh /var/* 2>/dev/null | sort -rh | head -10     # narrow down which directory
find / -type f -size +100M -mtime -2 2>/dev/null      # narrow down which large/recent file
```

### Q: Explain the practical difference between `find ... -exec CMD {} \;` and `find ... | xargs CMD`.
**A:**
- `-exec CMD {} \;` runs CMD once **per file**, one at a time.
- `-exec CMD {} +` and `| xargs CMD` **batch** multiple files into fewer command calls — generally faster for large numbers of files.

### Q: A script is supposed to accept a sentence as one argument (`./script.sh "hello devops world"`) but breaks on the spaces. What's the bug and fix?
**A:**
Unquoted `$1` splits on whitespace into multiple arguments. Always quote it:
```bash
sentence="$1"
```

### Q: You need a script that dispatches different logic based on an operation name passed as the first argument (like `start`, `stop`, `restart`). What construct fits, and how would you structure it?
**A:**
```bash
case "$1" in
    start)   echo "starting" ;;
    stop)    echo "stopping" ;;
    *)       echo "Unknown operation" ;;
esac
```

### Q: `df -h` shows plenty of free space, but you still get "No space left on device" creating a new file. What's going on?
**A:**
Likely **inode exhaustion**, not actual disk space — a filesystem can run out of inodes (common with huge numbers of small files) while bytes are still free.
```bash
df -i        # check inode usage specifically
```

---

### Q: After a reboot, a previously working data volume is missing and a dependent service won't start. Most likely cause?
**A:**
The volume was mounted manually (`mount`) but never added to `/etc/fstab`, so it doesn't auto-remount on boot.
```bash
cat /etc/fstab       # check/add the missing entry (device, mount point, fs type, options)
```

---

### Q: You run `ps aux` and see a process in state `Z`. What is it, and what should you actually investigate?
**A:**
A **zombie** — a finished process whose exit status hasn't been read by its parent yet. You can't kill a zombie directly (it's already dead); investigate/fix the **parent process** instead.

---

### Q: A "server is slow" ticket comes in. `uptime` shows load average `4.2, 3.8, 3.5`. Is that bad?
**A:**
Load average means nothing without core count:
```bash
nproc        # check CPU core count
```
A load of `4.2` is fine on an 8-core box, but overloaded on a 2-core box.

---

### Q: A service crashed with no error at all in its own application logs. What's an easily overlooked cause and check?
**A:**
Possible silent **OOM (Out Of Memory) kill** — Linux force-kills processes to save the system, without an error in the service's own logs.
```bash
dmesg | grep -i "out of memory"
journalctl -k | grep -i oom
free -h
```

### Q: You need to add a user to the `docker` group without removing their existing group memberships. Exact command?
**A:**
```bash
sudo usermod -aG docker <username>
```
`-a` (append) is critical — without it, `-G` **replaces** all existing group memberships.

---

### Q: A colleague runs `usermod -G developers newhire` (no `-a`). What just happened, and how do you verify?
**A:**
`newhire` lost membership in **every other group** they were previously in — only `developers` remains.
```bash
groups newhire
id newhire
```

---

### Q: You need to change ownership of `/var/www/app` to `deployuser:deployers`, recursively.
**A:**
```bash
sudo chown -R deployuser:deployers /var/www/app
```
(`chown` = ownership of files/folders. `usermod` = properties of a user account — never use `usermod` on a file path.)

---

### Q: A cron job that used to work now fails silently every night with no alert. Why, and what's the fix inside the script?
**A:**
Cron/CI-CD only react to a script's **exit code**. If a script fails but never explicitly exits non-zero, it returns `0` (success) by default — the failure is invisible to anything automated watching it.
```bash
if [ -z "$required_var" ]; then
    echo "Error: required_var not set"
    exit 1
fi
```

### Q: A script needs to wait and retry until a service is actually active, giving up after 5 attempts. What's the pattern?
**A:**
```bash
attempts=0
max_attempts=5
while ! systemctl is-active --quiet nginx; do
    attempts=$(( attempts + 1 ))
    if [ "$attempts" -ge "$max_attempts" ]; then
        echo "Error: nginx failed to start after $max_attempts attempts"
        exit 1
    fi
    sleep 2
done
echo "nginx is up!"
```

### Q: An nginx config was just edited and the service fails to restart. Walk through the diagnostic sequence.
**A:**
```bash
sudo nginx -t                    # test config syntax WITHOUT restarting
sudo systemctl status nginx        # quick error summary
journalctl -u nginx -xe             # detailed reason, jumped to newest entries
# fix the config, then:
sudo systemctl restart nginx
```

### Q: What's the difference between `kill <PID>` and `kill -9 <PID>`, and which do you try first?
**A:**
- `kill` (default, SIGTERM) — a polite "please shut down gracefully" request; the process can clean up first.
- `kill -9` (SIGKILL) — immediate, forceful termination with no cleanup; risks data corruption for a process mid-write.

Always try graceful `kill` first; escalate to `-9` only if it doesn't respond.

### Q: A file has permissions `-rwxr-xr-x`. Convert to numeric form and explain the digits.
**A:**
`755` — owner: `rwx`(7), group: `r-x`(5), other: `r-x`(5). (`r=4, w=2, x=1`, summed per group.)

---

### Q: A script fails with a permissions error only for a specific service account, `svc-deploy`. How do you check if group membership is the cause?
**A:**
```bash
groups svc-deploy
id svc-deploy
```

---

### Q: What's the real risk of editing `/etc/sudoers` directly with a normal text editor instead of `visudo`?
**A:**
A syntax error saved directly can **lock out all sudo access** system-wide, with no easy way to recover. `visudo` locks the file and validates syntax before saving, preventing this.

### Q: You need to find every file over 200MB anywhere under `/var`, modified in the last 3 days, to investigate a disk alert.
**A:**
```bash
find /var -type f -size +200M -mtime -3
```

### Q: You want to `chmod +x` every script in a directory at once instead of one by one.
**A:**
```bash
for file in *.sh; do
    chmod +x "$file"
    echo "Made executable: $file"
done
```

if [ -z "$DEPLOY_ENV" ]; then
